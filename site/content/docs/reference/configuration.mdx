---
title: Configuration
description: The complete configuration contract for .pi/hookit.json.
---

Configuration is plain JSON in `.pi/hookit.json` for the current project, or
`~/.pi/agent/hookit.json` for global policies. Project storage is only read
after Pi trusts the project. The **JSON Schema at
[`meffmadd/pi-assert/schema.json`](https://raw.githubusercontent.com/meffmadd/pi-assert/main/schema.json)
is the validation authority**: every designated JSON configuration example is
validated against it, and editors that understand JSON Schema use it for
autocompletion.

The persisted format has a top-level object with an optional `$schema`, an
optional `repos` array, and one Section per Hook Source (`local` plus one
`owner/repo` per installed repository). Every Section maps names to Catalog
Entries, which are either a **Hook** or a **Preset** — never both.

{/* docs-example:valid */}
```json
{
  "$schema": "https://raw.githubusercontent.com/meffmadd/pi-assert/main/schema.json",
  "repos": ["meffmadd/pi-assert-rules"],
  "local": {
    "no-env-access": {
      "description": "Blocks reads and writes to .env files.",
      "event": "tool_call",
      "filter": { "toolName": "^write$", "path": "(^|/)\\.env$" },
      "shell": "false"
    }
  },
  "meffmadd/pi-assert-rules": {
    "clean-turn": {
      "description": "Require a clean worktree after each turn",
      "event": "turn_end",
      "shell": "git diff --quiet"
    }
  }
}
```

## Top-level fields

| Field | Type | Requirement | Default | Applies to | Constraints | Behavior | Example |
|---|---|---|---|---|---|---|---|
| `$schema` | string | optional | — | storage root | The Schema accepts any string; use the canonical URL shown above. | Points schema-aware editors at validation and autocomplete metadata. | `"https://raw.githubusercontent.com/meffmadd/pi-assert/main/schema.json"` |
| `repos` | string array | optional | — | storage root | Items match `^[^/]+/[^/]+$` and are unique. | Lists repositories available to the `/hooks` installer and authorizes matching project repository Sections. | `["meffmadd/pi-assert-rules"]` |
| `local` | entry object | optional | — | storage root | Entry names follow the [identity rules](#entry-identity). No Section is required; `{}` is schema-valid. | Stores Hooks and Presets authored in this storage. | `"local": { "guard": { ... } }` |
| `owner/repo` | entry object | optional | — | storage root | The Catalog requires a canonical `owner/repo` key; a project Section must also appear in that storage's `repos`. | Stores Hooks and Presets installed from that repository. | `"meffmadd/pi-assert-rules": { ... }` |

At the JSON Schema layer, every non-reserved top-level key is validated as a
repository Section through the root `additionalProperties` schema. Hook Catalog
validation then rejects non-canonical Source keys and undeclared project
repository Sections. Hook and Preset records themselves reject unknown fields
with `additionalProperties: false`.

## Entry identity

Each entry name is **non-empty and contains neither `/` nor NUL**. The
source-qualified identity is the **Hook Reference**: `local/name` for local
entries or `owner/repo/name` for repository entries. References are how
Presets name members and how reports and Filters identify a Hook, so the
restriction keeps identity unambiguous:

| Catalog Entry name | Valid? | Notes |
|---|---|---|
| `no-env-access` | yes | ordinary local entry |
| `` (empty) | no | names are non-empty |
| `nested/guard` | no | `/` is reserved for Reference separators |
| `nul\u0000guard` | no | NUL is reserved for persisted enablement keys |

## Hook shape

A **Hook** subscribes to one Event and owns a shell decision and, optionally,
one Action. A Hook requires `description` and `event`, and **at least one of
`shell` or `action`**. Any other valid combination is allowed — `shell` and
`action` may appear together.

| Field | Type | Requirement | Default | Applies to | Constraints | Behavior | Example |
|---|---|---|---|---|---|---|---|
| `description` | string | required | — | every Hook | — | Supplies the human-readable summary shown in `/hooks`. | `"Block dotenv writes"` |
| `event` | string enum | required | — | every Hook | One of the 8 supported [Events](/reference/events). | Chooses the Event to which the Hook subscribes. | `"tool_call"` |
| `shell` | string | at least one of `shell`/`action` | canonical `"true"` when omitted | every Hook | Boolean values and unknown fields are invalid. | Runs the decision command; exact `true` and `false` use equivalent optimized shortcuts. | `"false"` |
| `action` | object | at least one of `shell`/`action` | — | every Hook | Exactly one owned Action using one supported variant. | Selects an [Action](/reference/action) against this Hook's result. | `{ "type": "interrupt", "outcome": "block" }` |
| `filter` | object | optional | — | every Event, with event-specific candidates | Values use the supported Filter union; `hook_result` permits only its bounded fields. | ANDs candidate criteria before an Invocation starts. | `{ "toolName": "^read$" }` |
| `when` | string | optional | — | every Hook | — | Runs a shell Precondition; ordinary non-zero skips the whole Hook. | `"test -f package.json"` |
| `default` | boolean | optional | `false` | Hooks and Presets | — | Enables the entry only when the session has no saved enablement set. | `true` |

Unknown fields on a Hook are rejected. Exact `"true"` / `"false"` shell values
are optimized shortcuts that behave and render as ordinary commands — see
[Shell semantics](/reference/events#shell-semantics). A Hook that only runs
its Action unconditionally omits `shell` and becomes an optimized canonical
`true` Hook.

## Preset shape

A **Preset** is a named list of unique Hook References. It enables a set of
Hooks as one unit and **cannot carry any executable field** (`shell`, `event`,
`action`, `filter`, or `when`).

| Field | Type | Requirement | Default | Applies to | Constraints | Behavior | Example |
|---|---|---|---|---|---|---|---|
| `description` | string | required | — | every Preset | — | Supplies the human-readable summary shown in `/hooks`. | `"Enable repository guards"` |
| `preset` | Hook Reference array | required | — | every Preset | References are unique and source-qualified; the array may be empty. | Expands available Hook members in reference order; see [Presets and sources](/reference/presets-sources). | `["local/no-env-access"]` |
| `default` | boolean | optional | `false` | Hooks and Presets | — | Enables the entry only when the session has no saved enablement set. | `true` |

A reference may `local/name` or `owner/repo/name`. An unresolved reference
remains valid and **dangling**; a reference that resolves to another Preset
fails the complete Catalog until nested Presets are supported.

## Explicitly invalid combinations

The Schema rejects combinations that cannot form a valid entry. This example
illustrates a boolean `shell`, which is invalid:

{/* docs-example:invalid */}
```json
{
  "local": {
    "mistake": {
      "description": "A Hook with an invalid boolean shell",
      "event": "tool_call",
      "shell": false
    }
  }
}
```

So are an entry with neither `shell` nor `action` (inert), and an entry that
mixes a Hook's fields with a Preset's `preset` array. If a file fails
validation, `/hooks` reports the Catalog as broken and refuses mutations until
the file is fixed, so your previously working session state is unaffected.
